# D365 F&O Data Agent

An AI-powered natural language query interface for Dynamics 365 Finance and Operations. Transform complex SQL queries into simple conversations and get instant insights from your ERP data.

## Overview

The D365 F&O Data Agent enables non-technical business users to query D365 data using natural language. Instead of writing SQL or navigating complex ERP interfaces, users simply ask questions in plain English and receive accurate, permission-filtered results.

**Key Capabilities:**
- Natural language to SQL query generation powered by AI
- Metadata-driven intelligence using D365 table/field definitions
- RAG (Retrieval Augmented Generation) for document-based context
- Azure AD authentication with role-based access control
- Excel export and data visualization
- Comprehensive query history and audit trail

## Features

### 🤖 AI-Powered Query Generation

Ask questions in natural language and receive accurate SQL queries generated by AI. The system understands your D365 schema through uploaded metadata and provides context-aware responses.

**Query Flow (Generate → Review → Execute):**
1. **Generate**: AI creates SQL based on your question
2. **Review**: You see the SQL query before execution
3. **Execute**: Click "Run Query" to get results

**Example Questions:**
- "Show me all purchase orders from last month"
- "Why can't we ship to customer ABC123?"
- "Which purchase orders could impact the production process?"
- "List all customers with credit limit over $100,000"

**AI Modes:**
- **Mode A**: Full schema provided, highest accuracy
- **Mode B**: Requests specific metadata files when needed
- **Mode C**: Infers standard D365 tables (DirPartyTable, CompanyInfo) from built-in knowledge

**Features:**
- Token usage and cost display ($0.02-0.05 per query typical)
- Confidence indicators (high/medium/inferred)
- CTE (Common Table Expression) support for complex queries
- Conversation history for multi-turn refinement
- Copy All Context button for documentation

### 📚 RAG Knowledge Base

Upload business documents (PDF, Word, Excel, Text, Markdown) to provide additional context for the AI. The system uses Retrieval Augmented Generation to reference relevant information when answering queries.

**Supported File Types:**
- PDF documents (.pdf)
- Word documents (.docx)
- Excel spreadsheets (.xlsx, .xls)
- Text files (.txt)
- Markdown files (.md)

**Use Cases:**
- Upload D365 configuration guides
- Include business process documentation
- Add data dictionaries and field descriptions
- Reference operational procedures

### 📊 D365 Metadata Management

Upload D365 AxTable XML metadata files exported from your environment. The system parses table definitions, field types, Extended Data Types (EDT), and relationships to provide accurate query generation.

**Metadata Features:**
- XML parser for D365 AxTable format
- Field type mapping (AxTableFieldString, AxTableFieldEnum, etc.)
- ExtendedDataType (EDT) extraction
- Relationship and foreign key detection
- Search and filter capabilities

### 🔒 Enterprise Authentication & Security

**Azure AD Integration:**

**Features:**

## Getting Started

### Prerequisites

**Required:**
- Azure SQL Database access to D365 F&O
- D365 metadata XML files (AxTable format)
- Azure AD account (or use dev fallback)

**Optional:**
- Business documents for RAG knowledge base
- Azure AD application registration (for production)

### Quick Start

1. **Sign In**
   - Navigate to the application URL
   - Click "Sign In" and authenticate

2. **Test Database Connection**
   - Go to "Connection Test" from top navigation
   - Enter Azure SQL credentials:
     - Server: `your-server.database.windows.net`
     - Database: `AXDB` (or your D365 database name)
     - Username and Password
   - Click "Test Connection"
   - Credentials are saved in localStorage for convenience

3. **Upload Metadata**
   - Go to "Metadata" from top navigation
   - Upload D365 AxTable XML files (e.g., `CustTable.xml`, `VendTable.xml`)
   - System parses and stores table/field definitions

4. **Upload Knowledge Base Documents** (Optional)
   - Go to "Knowledge Base" from top navigation
   - Upload business documents (PDF, Word, Excel, etc.)
   - System processes and indexes documents for RAG

5. **Start Querying**
   - Go to "Chat" from top navigation
   - Ask questions in natural language
   - Review generated SQL query
   - Click "Run Query" to execute
   - View results and export to Excel
   - Use "Copy All Context" to export conversation

### For Administrators

**Configure Azure AD (Production):**
1. Register application in Azure Portal
2. Set environment variables:
   - `AZURE_AD_CLIENT_ID`
   - `AZURE_AD_TENANT_ID`
   - `AZURE_AD_CLIENT_SECRET`
3. Configure redirect URI: `https://your-app.manus.space/api/auth/callback`
4. See `docs/deployment/azure-ad-setup.md` for detailed steps

**Manage Security Roles:**
1. Go to Settings → Security Roles
2. Add D365 security roles (e.g., "Purchasing Agent", "Finance Manager")
3. Go to Settings → Azure AD Mappings
4. Map Azure AD groups to D365 roles

## Architecture

### High-Level Overview

```
User Interface (React)
    ↓
tRPC API (Type-Safe)
    ↓
Backend Services (Node.js)
    ├── Authentication (Azure AD / Dev Fallback)
    ├── Query Generator (AI/LLM)
    ├── Metadata Parser (XML)
    ├── RAG Engine (Document Retrieval)
    └── Azure SQL Executor
    ↓
Data Layer
    ├── Internal DB (MySQL/TiDB) - Metadata, History, Users
    ├── Azure SQL (D365 F&O) - Production Data
    └── Vector Store (In-Memory) - Document Embeddings
```

### Technology Stack

**Frontend:**
- React 19 + TypeScript
- Tailwind CSS 4
- shadcn/ui (Radix UI components)
- tRPC + React Query
- Wouter (routing)

**Backend:**
- Node.js 22 + Express 4
- TypeScript
- tRPC 11 (type-safe API)
- Drizzle ORM
- MSAL (Azure AD)

**AI & ML:**
- LLM: OpenAI GPT-5.1-2025-11-13 (default), GPT-4o, GPT-4o-mini, Claude-3.5-haiku
- Token tracking: Real-time usage and cost estimation
- Embeddings: Xenova Transformers (local, MiniLM-L6-v2)
- Vector Store: In-memory (development)
- Query Modes: Mode A/B/C with confidence indicators

**File Processing:**
- pdf-parse (PDF)
- mammoth (Word)
- xlsx (Excel)
- markdown-it (Markdown)

**Testing:**
- Vitest (unit tests)
- 30+ passing tests

### Key Components

**Metadata Parser** (`server/metadataParser.ts`)
- Parses D365 AxTable XML files
- Extracts table/field definitions, types, EDTs
- Maps D365 types to SQL types

**Query Generator** (`server/queryGenerator.ts`)

**RAG Orchestrator** (`server/rag/RAGOrchestrator.ts`)

**Azure SQL Executor** (`server/azureSqlExecutor.ts`)
- Connection pooling
- Parameterized query execution
- Error handling and logging

**Authentication System** (`server/auth/`)
- Provider abstraction layer
- Azure AD OAuth provider
- Development fallback provider
- Role mapping and session management

- Only SELECT queries allowed (including CTE: WITH...SELECT)
- Dangerous keywords blocked (DROP, DELETE, INSERT, UPDATE)
- Parameterized queries prevent SQL injection
- All queries logged with user attribution
- Manual execution approval required (Run Query button)

- Azure AD OAuth (SSO)

- Secure cookie-based sessions
- Development fallback for testing

- HTTPS/TLS for all connections
- Environment variable-based credentials

- Audit trail for all data access

## Troubleshooting

### Connection Issues

**Cannot connect to Azure SQL:**
- Verify firewall rules allow your IP address
- Check credentials are correct
- Ensure server name format: `server.database.windows.net`
- Test connection from `/connection-test` page

**Database not available:**
- Check `DATABASE_URL` environment variable
- Verify MySQL/TiDB service is running
- Run `pnpm db:push` to ensure schema is up-to-date

### Metadata Issues

**XML parsing errors:**
- Ensure file is valid D365 AxTable XML format
- Check for `<AxTable>` root element
- Verify `<Fields>` section contains `<AxTableField>` elements
- Use CustTable.xml as reference

**Field types not recognized:**
- Check `i:type` attribute on `<AxTableField>` elements
- Supported types: AxTableFieldString, AxTableFieldInt, AxTableFieldEnum, etc.
- See `server/metadataParser.ts` for full type mapping

### Query Generation Issues

**AI generates incorrect queries:**
- Improve metadata descriptions (add business context)
- Upload relevant documents to Knowledge Base
- Rephrase question more specifically
- Check that metadata includes relationships/foreign keys
- Try Mode C for standard D365 tables (DirPartyTable, CompanyInfo automatically inferred)

**Query execution fails:**
- Verify Azure SQL connection is configured
- Check user has permissions on queried tables
- Review generated SQL for syntax errors (shown before execution)
- Click "Run Query" to execute after reviewing SQL
- Check query history for error details

**Token cost concerns:**
- Default model (GPT-5.1) costs $2.50/$10 per 1M tokens
- Use GPT-4o-mini ($0.15/$0.60) for budget-conscious scenarios
- Token usage displayed in UI for each query
- Typical query: $0.02-0.05

### RAG/Knowledge Base Issues

**Document processing fails:**
- Verify file format is supported (PDF, DOCX, XLSX, TXT, MD)
- Check file size (large files may take longer)
- Review server logs for processing errors

**Documents not referenced in queries:**
- Ensure documents are fully processed (check status)
- Try more specific questions related to document content
- Verify embeddings are generated (check database)
